The Keepit Power Platform and Dynamics 365 connector requests four permissions across three Microsoft APIs: Microsoft Graph, Dataverse, and the Power Apps service. This article lists each permission, its type, and its purpose.
How the permissions work
The connector does most of its work with delegated permissions, acting as the service account that created it. The roles assigned to that account, not the application permissions alone, determine what the connector can read and write in each environment.
Power Platform and Dynamics 365 enterprise application permissions
The connector requests the following permissions when you create it and grant consent.

The sign-in also requests the standard OpenID Connect scopes openid, profile, and email. These scopes identify the signed-in account and grant no access to tenant data.

Because three of the four permissions are delegated, the service account needs its own roles in Microsoft Entra ID and in each environment.
Global Administrator role
You need the Global Administrator role to install the Keepit enterprise application and grant admin consent when you create the first connector. You’re prompted for permissions only the first time you create a connector.
You can remove the Global Administrator role after you create the connector. You must reassign it to reauthenticate the connector. For instructions, see Remove the Global Administrator role from a Power Platform and Dynamics 365 backup service account.
For the licenses the service account needs, see Requirements for a Power Platform and Dynamics 365 backup.
Important: The required permissions can change as Microsoft changes its APIs and as we add coverage. We don’t officially support restricted or custom roles until we’ve fully tested them.
Backup and restore permissions
Backup and restore use the same permissions. Restore doesn’t use a separate or wider set. Each permission works as follows:
Microsoft Graph provides read-only access for the directory lookups described earlier. The connector doesn’t write to the directory.
Dataverse user_impersonation covers both reading data for backup and writing data back for restore. Write access comes from the service account’s System Administrator security role in the environment.
The Power Apps service User permission lets the connector export canvas app packages for backup.
